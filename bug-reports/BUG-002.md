# BUG-002 - Train dry-run reports readiness with an empty model identity

Evidence links are public derivatives; unchanged originals are supplied separately. See [evidence policy](../evidence/README.md).

## Environment

Soup CLI 0.77.2; Python 3.11.16; Arch Linux x86-64. [Original environment manifest](../evidence/derived/logs/stage-3/20261110T091544Z-pytest-56cb4d/manifest.json).

## Preconditions

Complete the base installation in [README](../README.md). Use the retained 20-row synthetic fixture. No GPU or model download is required. The [positive control](../evidence/derived/logs/stage-3/20261110T091544Z-pytest-56cb4d/001-positive-control/) passed before negative tests.

## Steps to reproduce / minimal example

1. Inspect the [complete input](../evidence/derived/logs/stage-3/20261110T091544Z-pytest-56cb4d/132-empty/input.yaml). The minimal change is `base: ''`; other settings retain the valid baseline.
2. From the repository root, run:

   ```sh
   .venv/bin/python -m scripts.replay_case evidence/derived/logs/stage-3/20261110T091544Z-pytest-56cb4d/132-empty --repeat 1
   ```

The helper creates fresh evidence and calls `soup train --config input.yaml --dry-run`. Its expected rejection fails, so the helper returns 1 while Soup returns 0.

## Expected

Reject with train config-error exit 1, name `base`, and do not announce readiness. The [schema description](../evidence/derived/logs/stage-5/inspection/source/config/schema.py) requires a model name/path; an empty string supplies neither in this fixture. This is a semantic QA interpretation, not an explicit schema minimum-length constraint or an offline demand to check remote availability. [Train help](../evidence/derived/logs/stage-4/preparation/train-help/stdout.txt) promises config validation. A [missing-base control](../evidence/derived/logs/stage-3/20261110T091544Z-pytest-56cb4d/124-empty/) correctly exits 1.

## Actual

Soup exits **0**, displays a blank `Model:`, reports 18 train / 2 validation rows and prints `Config valid. Ready to train!`. There is no base diagnostic; stderr is empty.

## Severity: Low

The validation message can mislead setup checks. No actual model-loading failure, fallback model, wasted GPU time or wrong weights were demonstrated.
